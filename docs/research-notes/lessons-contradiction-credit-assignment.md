# Lessons Memory: Contradiction, Credit Assignment, and Decay

**Date:** 2026-11-02 · **Status:** Research note for Gate 9 (reflector cross-lesson contradiction pulses)
**Scope:** What is the correct design for (a) deciding which prior lessons a correction bears on, (b) whether cross-topic injected memories should ever change status from a correction, and (c) how decay handles staleness and unconfirmed lessons — without letting the agent keep repeating the same mistake.

## 1. Our current code (source #1)

- `sidecar/src/learning/reflector.ts` — `deduceSignals()` (l. 37–47) turns a turn into `{error, correction, clean}` from a regex on the user text. In `drain()`, after the reflect call, the loop `for (const lessonId of observation.injectedLessonIds)` (l. 137–143) pulses **every** lesson injected into that turn with whatever signals the turn produced; only the turn's own freshly-written/duplicate lesson is exempted (l. 128–135, 139–141: "the mistake proves the lesson matters, it does not falsify it"). A correction turn therefore gives `-0.2` (`SIGNAL_WEIGHTS.correction`) plus a `contradictions += 1` to bystander lessons about unrelated topics.
- `sidecar/src/learning/ledger.ts` — `SIGNAL_WEIGHTS` (l. ~22): clean `+0.06`, error `-0.1`, correction `-0.2`, userConfirm `+0.08`; `CLAMP` to `[0.05, 0.95]`; `decayedConfidence()` halves confidence weekly (`DEFAULT_HALF_LIFE_WEEKS = 1`) but never below the `0.05` floor — old evidence "just stops earning its injection slot."
- `.orchestrate/pi-engine/gates.md` Gate 9 records the bug-suspect: a deploy-order fix also shaved an injected file-naming lesson. The lane kit films with `injection_floor=0.99` to route around it.

**The bug, stated as a credit-assignment error:** co-presence in the context window is *not* evidence. A correction is a signal about **which** belief caused the mistake. Pulsing every injected lesson treats membership in the prompt as causal contribution — the exact error the credit-assignment literature warns against. In reinforcement learning, the temporal credit-assignment problem is to distribute credit/blame only to the states and actions that contributed to the outcome (Sutton & Barto, *Reinforcement Learning: An Introduction*, 2nd ed., MIT Press 2018 — book page archived from the authors' official site: <https://web.archive.org/web/2025/https://incompleteideas.net/book/the-book-2nd.html>). In case-based reasoning, reinforcement similarly only flows to cases that were **retrieved and reused** for the solution (Aamodt & Plaza, "Case-Based Reasoning: Foundational Issues, Methodological Variations, and System Approaches," *AI Communications* 7(1), 1994: <https://doi.org/10.3233/aic-1994-7104>).

**Consensus across all six systems: none of them changes the status of unrelated memory because it happened to be injected.** Every update is retrieval-gated (mem0, A-Mem, LangGraph collections), target-addressed (Letta blocks, Anthropic files), or contradiction-pair-resolved (Zep). No system does a "blanket pulse over everything in context."

## 3. What we should adopt (mapped to `reflector.ts`)

**(a) Which lessons does a correction bear on?** Two sources, joined:
1. The lesson the store itself implicated — already handled: the reflect reply's `lessonId` is exempt from the turn's own correction pulse (reflector.ts l. 128–135, 139–141). Extend the store's reflect reply to also name **contradicting lesson IDs** when a duplicate/correction resolves against a specific prior lesson.
2. Client-side retrieval overlap: embed (or BM25, like mem0's `score_and_rank` threshold gate) the correction turn's user text against the text of every `observation.injectedLessonIds` entry; pulse negatives only where the score clears a floor. Co-presence with score-below-floor = `NONE`, exactly mem0's plan.

**(b) Cross-topic injected memories: never change status from a correction.** Attribution must be pairwise (a correction vs. a specific lesson), the way Zep resolves a contradiction to one edge and mem0 resolves a fact to the retrieved candidates it contradicts. Presence in the injection set is not evidence for or against a lesson. Concretely: in reflector.ts l. 137–143, replace the unconditional `this.ledger.pulse(lessonId, signals)` with a floor gate — `if (signals.correction || signals.error) { pulse only if overlap(lesson, correctionText) >= floor; else skip }`. Keep `recordInjection` side-effect-free of trust (injections count usage, not correctness — ledger.ts `state.injections` already serves this cleanly).

**(c) Decay without evading repeated mistakes:**
- Keep the weekly half-life (`decayedConfidence`, ledger.ts) — it is the right mechanism for **staleness**: unconfirmed evidence stops earning its slot without ever being erased, matching how Letta/Zep/LangGraph let retrieval, not scoring, handle freshness.
- Repeated mistakes on the *same* lesson stay fully armed: once negatives are floor-gated, `-0.2` per correction accumulates only where the correction really contradicts the lesson; `acknowledgeCount`-style `state.contradictions` rises as is (ledger.ts `pulse()`). With mem0/Zep as the model, note that repeated *contradictions* should eventually change the lesson's **content** (an UPDATE/DELETE in the store), not just its number — recommend: after a contradictions threshold (e.g. 2–3), the reflector writes a revised/retracted lesson instead of continuing to decrement. This is what keeps the agent honest about mistakes it makes repeatedly, without bystander lessons paying for them.
- What to **avoid**: blanket decay — a pulse (or decay kick) applied to every injected memory each turn. It trains the wrong conditional: "being in context is risky," which makes retrieval-injection self-defeating (the more the agent retrieves, the faster unrelated lessons rot).
- Zep's admission gating adds one extra safeguard we partially have: don't let a single correction *or* a single success move a lesson much; require accumulated confirmations (`userConfirm`/clean-run evidence) before a lesson graduates — which the base-0.55 start, capped pulses, and 30-day scrub already approximate.

**Minimal change (Gate 9 fix unit):** in `sidecar/src/learning/reflector.ts`, gate the negative pulses inside the `injectedLessonIds` loop (l. 137–143) behind a retrieval-overlap floor computed from the observation's correction/error text vs. the injected lesson's text; leave the low-magnitude `clean` confirm as-is (it is cheap, capped at `0.95`, and merely slows decay rather than manufacturing credit), or optionally floor-gate it in a second pass to match strict single-case eligibility.
